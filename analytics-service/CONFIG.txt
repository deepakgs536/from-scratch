==========================
ANALYTICS SERVICE CONFIGURATION
==========================

ENVIRONMENT VARIABLES
---------------------
To run this service, the following environment variables can be configured:

- AWS_REGION
  Description: The AWS region to use for DynamoDB and other services.
  Default: us-east-1

- ANALYTICS_TABLE
  Description: The DynamoDB table name for storing analytics data.
  Default: AnalyticsTable

- DYNAMODB_ENDPOINT
  Description: Optional endpoint for local testing (e.g., LocalStack or dynamodb-local).
  Default: undefined

- LOG_LEVEL
  Description: Sets the logging level. Options: INFO, DEBUG, WARN, ERROR.
  Default: INFO

==========================
DYNAMODB TABLE CREATION
==========================

When creating the DynamoDB table in AWS, you MUST include the following key schema:

- Table Name: AnalyticsTable (or match your ANALYTICS_TABLE environment variable)
- Partition Key: PK (Type: String)
- Sort Key: SK (Type: String)
- Billing Mode: On-Demand (recommended) or Provisioned depending on your load.

These keys are strictly required because the application uses a single-table design and relies on `PK` and `SK` to store different types of aggregated metrics in the same table.

==========================
API ENDPOINTS & RESPONSES
==========================

All endpoints should be prefixed with your API Gateway base URL.
All API responses are formatted as JSON.

1. GET /health
---------------------
Description: Health check endpoint to verify the service is running.
Response:
{
  "status": "ok"
}

---------------------
